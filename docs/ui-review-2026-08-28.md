# UI 审查与框架选型方案存档

日期：2026-08-28

审查依据：完整源码（`app/` 下所有组件 + 1914 行 `app/globals.css`）+ `http://localhost:8787` 实际渲染内容（curl 抓取）。本文档只给出建议，不包含任何代码改动。

## 一、UI 问题清单

### A. 信息准确性（数据产品最致命的一类）

| # | 问题 | 位置 | 建议 |
|---|------|------|------|
| 1 | **「最快首字」卡片在说谎的边缘**：取的是综合排行第 1 名（按 score 排）的 TTFT，不是真正 TTFT 最小的模型。当前数据恰好第一就是最快，纯属巧合；一旦排名和最快不一致，卡片直接给出错误信息 | `app/dashboard.tsx` L68、L191 | 改为对 `ttftValues` 取 min 并记录对应模型 |
| 2 | **页脚「系统运行正常」永远亮绿灯**：与 `refreshStatus.error`、`isStale` 完全无关联。数据过期时顶栏显示黄色「数据可能已过期」，页脚却绿点「系统运行正常」，自相矛盾 | `app/dashboard.tsx` L328-339 | 状态应派生自同一数据源 |
| 3 | **刷新失败的 error-banner 放在页面最底部**（表格之后），用户大概率看不到关键错误 | `app/dashboard.tsx` L324 | 移到顶栏下方或 hero 之上 |
| 4 | **TPS 数据样本无统计意义却原样展示**：探测 prompt 是 "Reply with exactly: pong"，多数模型只生成 1~2 个 token，出现了 `0.1 t/s`、`1.4 t/s` 这类数字，还参与综合分排序。UI 没有任何「样本不足」标注，会损害整个榜单的可信度 | `app/components/evaluation/model-evaluation.tsx`、评测逻辑 | completionTokens 低于阈值（如 <16）时 TPS 显示为「样本不足」或降权展示 |
| 5 | **信息冗余**：「刷新周期 1 hr」是写死的常量，其 detail「上次：30 分钟前」与「可用模型」卡的 detail「上次刷新: 30 分钟前」完全重复。4 张 metric 卡有 2 张携带相同信息 | `app/dashboard.tsx` L183-202 | 腾出的卡位可放更有价值的指标（如成功率、P95） |

### B. 可读性与信息架构

6. **厂商概览的三个数字没有标签**：`1157ms · 1856ms · 2739ms` 裸排，首次访问者不知道是 min/median/max；绿黄红配色也没有图例。区间条没有刻度轴，hint 文案只能解释相对顺序，无法读出量级。
7. **表格里有一列无名色条**（`aria-hidden` 的空表头 + `lat-band`）：它是 score 的可视化，但用户无从得知；而综合分公式（排序核心依据）藏在 `?` tooltip 里，过于隐蔽。建议给这列正名或合并进 score 列，公式说明提级。
8. **字号普遍低于可读下限**：表头 9px、状态列 9px、fastest-badge 9px、footer 10px、eyebrow 10px，大量正文 10-11px。9px + uppercase + letter-spacing 的表头基本不可读，建议正文下限 11px、数据标签下限 10px。
9. **行展开详情信息过载**：6 个指标卡 + 完整 JSON（含模型完整 think 内容，实测 minimax-m2.7 那条非常长）+ 3 条「计算」。其中「首字耗时计算 TTFT = 1,157 ms」只是复述上面的数字，零信息增益。建议：计算区只保留 TPS 一条（唯一真有公式的），JSON 折叠为二级或只留复制按钮。
10. **颜色语义过载**：同一页面颜色同时承担 ①厂商身份（8 色彩虹）②速度档位（绿黄红）③分数档位（绿黄红）。且 TTFT 分档阈值 500/1500ms 对实际数据（最快 1157ms）过严——绿档永远不出现，分档形同虚设。阈值应按当前数据分布动态分位，或改用连续色标。

### C. 交互

11. **「配置导出」下拉的隐式自动复制**：选中即复制 + 屏幕正中（`top: 30%`）弹大 toast。问题有三：①「选中=复制」没有任何前置提示（placeholder 是 hidden option）；②同一项选第二次不会复制（`lastAutoTarget` 去重），行为不一致；③toast 位置遮挡视线。建议改为显式复制按钮，或至少在 label 写明「选择后自动复制」，toast 移到顶部/底部边缘（Sonner 的默认位置就很好）。
12. **Tab 语义混用**：`role="tablist"` 里的按钮用的是 `aria-pressed`，正确组合是 `role="tab"` + `aria-selected` + 方向键导航。页面有 4 套 segmented control（语言切换 / page-tabs / view-toggle / metric-tabs），宽度、字号、激活色各不相同（amber vs cyan），建议收敛成一个组件。另外 `view-toggle` 独自居中（`margin: 24px auto`），与全局左对齐布局脱节。
13. **手写 SVG 趋势图缺交互**：无 hover tooltip（只有原生 `<title>`）、X 轴只有首尾两个日期标签、Y 轴无单位、小屏 `min-width: 760px` 横向滚动。这是最值得换库的地方（见第二部分）。
14. **语言闪烁**：SSR 固定输出中文，hydration 后才按 localStorage/navigator 切英文，英文用户会看到一闪而过的中文；`app/layout.tsx` 的 `lang="zh-CN"` 也是写死的。

### D. 视觉细节

15. **Inter 字体声明了但从未加载** ⚠️：`globals.css` 和 brand mark SVG 都引用 Inter，但 `app/layout.tsx` 没有用 `next/font` 或 `@font-face` 引入。除本机恰好装了 Inter 的用户外，全站实际渲染的是系统回退字体。建议用 `next/font/google` 加载（零 layout shift、自托管、对 Cloudflare 部署友好）。
16. **顶栏元素过密**：geo chip + 状态 chip + 时间戳 + 语言切换 + GitHub + 刷新按钮一行排开，窄屏 wrap 后凌乱；且 geo 信息在顶栏和页脚各出现一次，页脚还直接展示 `::1` 这种对访客无意义的 IP。
17. hero 设了 `min-height: 128px` 但右侧完全空着（`justify-content: space-between` 只有一个子元素）。
18. 3 个无限 pulse 动画（顶栏状态点、geo 点、页脚状态点）同时呼吸，静态页面略显干扰。`prefers-reduced-motion` 已处理，这点做得好。

### E. 可访问性

19. **缺全局 `:focus-visible` 样式**（只有 `legend-help` 有），深色背景下键盘导航焦点基本不可见。
20. `--ink-faint: #5A7380` 在 `#0A1118` 上对比度约 4:1，却大量用于 10-11px 小字，不达 WCAG AA（小字需 4.5:1）。

## 二、UI 框架选型建议

现状：Next.js 15.5 + React 19.1，App Router + Cloudflare（OpenNext），1914 行手写 `globals.css`，CSS 变量已 token 化（`--bg/--panel/--line/--ink/--amber…`），无 Tailwind、无组件库、图表为手写 SVG。

结论：**这个项目的视觉是高度自定义的暗色监控风格，CSS 变量 token 是资产。不建议引入「自带完整主题」的库把现有风格盖掉。** 主流方案对 Next.js 15 + React 19 的兼容性已确认，按迁移成本分三档：

### 方案 1（首选）：保留手写 CSS，只补「交互骨架」——Radix Primitives + Recharts

| 引入 | 替换什么 | 收益 |
|------|---------|------|
| **Radix UI Primitives**（headless，无样式） | 手写 tabs、`<details>`、CSS tooltip、原生 `<select>`、toast | 直接修复问题 11、12 的无障碍语义债；headless 不碰现有 class 和视觉，迁移成本最低 |
| **Recharts v3**（官方支持 React 16–19，SVG 渲染） | `app/components/trends/trend-analysis.tsx` 里约 140 行手写 SVG 图表逻辑 | 免费获得 hover tooltip、响应式、图例交互、accessibility layer（v3 默认开启）；颜色直接传 `providerColors`，现有配色无缝保留。数据量（11 模型 × 7 天）远在 SVG 舒适区内 |
| **lucide-react** | 手写 SVG icon 和文字符号（`↻ ◌ ⌁ ✓`） | 图标风格统一 |

不动 1914 行 CSS，一个下午能落地，专治交互和图表两块短板。

### 方案 2（长期）：Tailwind CSS v4 + shadcn/ui

如果项目会持续迭代，这是生态最优解：

- shadcn/ui **官方明确支持 Next.js 15 + React 19**（<https://ui.shadcn.com/docs/react-19>），组件以源码形式拷入项目，可完全掌控样式；
- 主题系统就是 CSS 变量，可以把现有 `--bg/--panel/--ink/--amber` 一一映射到 shadcn 的 theme token，**暗色监控风格可以完整保留**——但必须覆盖默认 token，否则会退回「shadcn 模板脸」；
- 一次拿齐 Table / Tabs / Accordion / Tooltip / Select / Badge / Card / **Sonner（toast，直接解决问题 11 的 toast 位置和动效）**，内置 chart 组件底层就是 Recharts；
- Tailwind v4 是构建期编译，对 OpenNext/Cloudflare 部署无任何运行时影响；
- 成本：1914 行 CSS 的迁移工作量大，建议**增量式**——新组件走 shadcn，旧区块逐步替换，两套样式可长期共存。

### 方案 3（参考）：Tremor

Tailwind + Recharts 之上的 dashboard 专用组件库（metric card、chart、table 开箱即用），风格就是监控面板。如果走方案 2，可以参考它的 dashboard 区块组织方式；但它对 Tailwind 强依赖且主题定制深度不如 shadcn，不适合作为独立方案叠加在现有手写 CSS 上。

### 不建议

- **Ant Design / MUI**：视觉风格强势、bundle 大，与现有自定义暗色风格冲突，会抹平项目辨识度；
- **ECharts**：能力过剩（10 万点级场景才需要），当前量级 Recharts 足够，没必要引入配置式 API 增加心智负担。

## 三、优先级建议

按投入产出比排序，如果只做三件事：

1. **问题 1 / 2 / 3**（状态一致性）：纯逻辑改动，改动极小，直接消除「页面自相矛盾」；
2. **方案 1 引入 Recharts**：替换手写趋势图，交互体验提升最明显；
3. **问题 15（加载 Inter 字体）**：一行 `next/font` 的事，全站字重视觉立刻提升。
